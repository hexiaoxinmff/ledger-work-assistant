# 文件格式转换：能力选择与核验

## v0.34 按确认列数拦截结构错误
若已确认应为三列，附加 `--expected-columns 3`。例如分号 CSV 错用逗号读取，可能变成一列；工具会停止且不生成输出。预期列数必须来自用户、模板或已确认的结构，不可直接复制本次解析结果。支持范围为 1–16384；未指定时维持旧版行为，不能自行假设列数。列数相同不代表字段对应、表头或内容正确，仍须检查。

## v0.33 TSV 与明确分隔符
包内 `tools/format-conversion/convert_table.py` 支持 TSV→XLSX 与 XLSX→TSV，TSV 固定制表符。CSV 默认逗号；如原件或使用者明确指定分号、制表符，可使用 `--delimiter semicolon` 或 `--delimiter tab`。选错分隔符可能得到一列且仍能完成回读，因此必须先核对预期表头、列数和样例，不将回读一致当作语义正确。保留编码选择，文本输出仍固定 UTF-8 BOM。

例如 `python tools/format-conversion/convert_table.py input.tsv output.xlsx`，或 `python tools/format-conversion/convert_table.py input.csv output.xlsx --delimiter semicolon`。原有显示格式、公式样文本、列数与覆盖保护继续适用；TSV 同样不保存列类型，直接用表格软件打开仍可能改变长编号。虚构样例覆盖长编号、空值、内含制表符/分号/逗号/双引号/换行的字段及往返回读；不代表所有外部系统 TSV 方言都兼容。

此文件定义工作流程，不代表本技能自带所有转换器。遵循用户指定的源文件、目标格式、范围、模板和平台权限；保持原件，另存新文件，避免覆盖。先检查文件能否读、类型与扩展名是否匹配、文件数量及页数/工作表、加密和损坏状态；信息已明确不重复询问。

## 根据任务选择
- Word / 可编辑文档 → PDF：优先平台实际可用的文档导出功能；检查页数、文字、表格、分页、图像与字体，页面显示是否核验需如实报告。
- PDF → Word：可提取文本与扫描件分流；按需使用 PDF 文本提取、文档生成或 OCR/视觉工具；重建为可编辑文档不保证原排版，必要时请用户确认文字优先还是版式优先，含表格时检查列对齐与数字。
- Word、PDF 或图片 → Excel：依 `document-to-excel.md` 转换、追踪、逐项核查数字；扫描件须依赖实际 OCR 能力。本包内简单 DOCX 文本表格导出单元格明细，不等于复原原表；v0.38 可为文字层中唯一且字符核验一致的数字候选附 PDF 页内坐标辅助定位，重复值或索引不一致时留空；不猜表格列、不能处理扫描文字。
- Excel / CSV ↔ 另一种表格格式：确认工作表、编码、分隔符、字段及目标文件；CSV 不保存多个工作表、格式、合并、图片或公式逻辑。多表转 CSV 须明确输出哪些表和命名，保留原始值并检查前导零、长数、日期、小数、符号、空值和行列数。不能仅凭扩展名或原表显示来推断数值原貌。
- Excel → PDF：确认要导出的工作表与打印范围，检查分页、表头、宽表、空白页及数字；不得声称未做的页面检查。
- 图片格式互转（如 PNG/JPEG）：依平台实际工具完成，确认尺寸及透明背景是否重要；JPEG 不支持透明背景且有损，不能擅自承诺无损或保留所有元数据。图片转 PDF 时检查顺序、方向与可读性。
- 其他格式：根据用户目标检查平台实际转换工具，能力不足时按 `skill-discovery.md` 发现并核查；无可用工具则报告限制，不能把改扩展名说成转换完成。

## 数字和交付核验
数字、编号、金额、表头和来源按 `document-to-excel.md` 逐项核对；不确定的字符标待核实，空值不当零。不因转换擅自修改金额、精度、币种或日期。输出前后检查源文件与目标文件，重新打开目标核对实际范围、页/表/行数量、重点数值和异常；对页面呈现和功能性未做的检查明确说明。只在实际完成、验证相应内容后才声明完整、可编辑、原样或无损。不得自动上传原始资料到额外服务。


## 包内 CSV / XLSX 互转工具（v0.18）
`tools/format-conversion/convert_table.py` 使用 Python 与 openpyxl 本地运行；CSV→XLSX 将所有值按文本保存，默认 UTF-8（兼容 BOM），可显式选 utf-16、gb18030、gbk，空行或列数不齐拒绝。XLSX→CSV 默认仅单表，多表需 `--sheet`；拒绝合并、公式、错误值及可能被电子表格执行的文本。CSV 不保存格式、图片、公式、工作表与数字格式；Excel 的数值显示格式或在源文件中已丢失的前导零和精度无法恢复。输出独占创建、源哈希检查和结果回读不能证明内容本身正确。脚本使用 openpyxl，环境若无依赖须按实际权限处理；尚未覆盖复杂表格或真实资料。

示例：`python tools/format-conversion/convert_table.py input.csv output.xlsx --encoding utf-8-sig`；`python tools/format-conversion/convert_table.py input.xlsx output.csv --sheet Sheet1`。

## XLSX 显示格式和 CSV 数字（v0.27）
XLSX → CSV 默认遇到日期或非 General 数字格式时停止并指出单元格，例如底层 123 以 `00000` 显示为 00123、百分比、金额小数位和日期。应让使用者确认所需的是原表显示还是底层值，并检查其他相关单元格；不能把底层值当成显示文本。如使用者明确接受底层值及格式丢失，可附加 `--allow-display-loss`，但仍会拒绝公式、错误值及其他不支持情况；日期按程序读取的值写出，不保证原显示。该检查不保证发现所有显示与底层值差异，也无法恢复原表已丢失的精度或前导零。

CSV 字节本身不保存单元格类型；即使文件里保留了完整长编号与前导零，表格软件直接打开时仍可能自动转换或舍入。需要在软件导入时将编号列指定为文本，并与原件逐项复核；若需要明确保留文本类型，优先使用 XLSX 文本单元格。程序回读 CSV 只证明文件内容一致，不证明软件打开后的显示或精度。

## 转换结果安全发布（v0.28）
CSV/XLSX 互转先在输出同目录生成 `.ledger-conversion-` 临时文件，并在临时文件上回读、比对转换内容和输入哈希；全部通过才借助硬链接创建最终路径。若最终文件已存在或目录不支持硬链接，程序停止且不覆盖已有文件。临时文件含转换结果，可能含敏感内容；进程异常或系统中断后应由使用者确认并按资料保护要求清理。已在本机虚构样例验证模拟写入失败、回读失败、输入变化及双进程同路径竞争；网络盘、断电和真实资料没有验证。


## v0.39 CSV 公式前缀防护

XLSX → CSV 对可能被电子表格解释为公式的文本采取拒绝导出策略。除 ASCII =、+、@、制表符、回车和非数值的 - 前缀外，也拒绝以换行符和全角 ＝、＋、－、＠ 开头的值；普通 ASCII 负数如 -12.00 仍可导出。虚构回归在 Python 3.12 的 GitHub Actions Ubuntu 和 Windows runner 上通过；未验证 Excel/LibreOffice GUI 打开、另存后的行为，也未使用真实账目测试。来源参考：OWASP CSV Injection（https://owasp.org/www-community/attacks/CSV_Injection）。


## v0.46 前导空白后的公式风险

XLSX → CSV 检查单元格文本时，会先检查去掉前导空白后的内容是否以公式前缀开头；若有前导控制字符，或去空白后出现 `= + @` 及全角变体，拒绝导出，原始文本不改写。以空白开头的普通负数仍按数值格式规则检查。该保守拦截避免用户打开 CSV 时，表格软件去除前导空白后把内容解释为公式；需人工审阅该单元格并决定安全导出方式。回归仅验证工具拦截逻辑，不代替 Excel/WPS/LibreOffice 实际打开测试。
