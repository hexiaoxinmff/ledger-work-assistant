# 文档转 Excel：数字准确性与复核

1. 确认文件、页数及目标（全部或指定页面、表格、输出模板）；仅追问影响转换的内容。先识别可选取文字、扫描 PDF、图片或 Word 表格，按照实际权限选择现有工具。
2. 可提取文字优先直接提取；图片/扫描件使用当前平台实际可用的 OCR 或视觉工具，逐页核查页数与表格。识别不到时标记待核实，不得补猜、编造或推断。不能读取时如实说明。
3. 数字按原文逐字符核对：符号、负号/括号、小数点、千分位、单位、币种、前导零、长编号和空值；未经确认不做单位转换、四舍五入或删去前导零。编号和长数字保存为文本，避免 Excel 自动转科学计数法或截断。必要时保留原文列和另行确认的数值列。对于不清楚、截断或可能混淆的字符，单列来源位置和候选，不生成确定值。
4. 不仅检查合计，还要逐格核对数字与原文；标注文件、页码及表/行/列，不能定位页码时如实标注。核对输出读取后的记录数、每个数字和来源；来源不清或未检查不得说完全准确。合计不一致列异常，不能倒推改写原值。
5. 输出新 Excel 和待核实清单，说明处理范围、识别方式、实际检查和未检查项，不覆盖原文。涉及真实数据是否发送到平台/OCR 服务按实际权限与组织要求执行。

`tools/document-to-excel/docx_tables.py` 为简单 DOCX 表格文字提取工具，不执行 OCR，不提取表格外文字、页码、页眉或图片；表格中包含合并单元格、嵌套表格或无法处理的结构时拒绝，不假定数字正确。文件只读、输出独占新建，输出结构化表格、单元格坐标明细及含数字原文复核清单，以文本保存并回读校验；结构化表格不保留原格式，复核清单按字符是否为数字筛选，并不代表已核对或覆盖所有模糊数字。用户需结合原文复核；遇到 PDF、照片、纯正文或复杂表格，使用当前平台工具或明确说明不能完成。

可搜索 PDF 的文字层可使用 `tools/document-to-excel/pdf_text_to_excel.py`，依赖 pypdfium2 与 openpyxl。它按 PDF 页导出原文分块、数字候选、上下文与页内字符偏移，并在同值唯一、搜索文本和字符范围一致时附加 PDF 页面坐标（PDF canvas units）辅助定位；重复值、字符索引不一致或边界框异常均留空并标记未定位。坐标不是视觉识别或数字正确性证明。工具不自动恢复表格行列，也不做 OCR；PDF 内作为图片的文字、矢量转曲文字和批注可能未提取。逐页状态会区分有文字层与未发现文字层；混合 PDF 中无文字页可能是扫描页、空白页或字体编码异常，不能假定业务内容为空。全 PDF 未发现文字层时停止，改走扫描件 OCR/人工流程。输出使用新路径，临时 XLSX 回读核验及源哈希通过后才以硬链接发布；文件系统不支持硬链接时停止。需逐页对照原 PDF 检查文字顺序、数字、标点、空白和遗漏；本地合成样例测试不代表真实 PDF 的提取准确率或版面还原能力。


## DOCX 结果安全发布

简单 DOCX 表格导出先写入输出目录中的临时 XLSX，完成源文件哈希复核、结构化明细/表格/数字复核清单回读后，再以硬链接原子发布到目标路径。遇到写入、回读或源文件变化时不发布目标文件，并清理临时文件；若文件系统不支持硬链接或目标已存在则停止，不覆盖已有结果。中断时可能遗留 .ledger-docx- 临时文件，需按原文资料保护要求检查。该流程只证明输出结构与提取结果一致，不证明 DOCX 中的数字业务含义正确。


## PDF 数字候选的边界

PDF 文字层数字候选要求完整词项边界：数字不得与字母、下划线、点号或逗号粘连。这样可避免把 `123ABC`、`1.2.3`、`1,23` 等混合或异常格式切成看似完整的数字片段。它仍是候选筛选，不是数字识别或格式校验；遇到不规范数值时必须回看页面原文，工具不会替用户修正或猜测。
