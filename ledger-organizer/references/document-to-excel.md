# 文档转 Excel：数字准确性与复核

1. 确认文件、页数及目标（全部或指定页面、表格、输出模板）；仅追问影响转换的内容。先识别可选取文字、扫描 PDF、图片或 Word 表格，按照实际权限选择现有工具。
2. 可提取文字优先直接提取；图片/扫描件使用当前平台实际可用的 OCR 或视觉工具，逐页核查页数与表格。识别不到时标记待核实，不得补猜、编造或推断。不能读取时如实说明。
3. 数字按原文逐字符核对：符号、负号/括号、小数点、千分位、单位、币种、前导零、长编号和空值；未经确认不做单位转换、四舍五入或删去前导零。编号和长数字保存为文本，避免 Excel 自动转科学计数法或截断。必要时保留原文列和另行确认的数值列。对于不清楚、截断或可能混淆的字符，单列来源位置和候选，不生成确定值。
4. 不仅检查合计，还要逐格核对数字与原文；标注文件、页码及表/行/列，不能定位页码时如实标注。核对输出读取后的记录数、每个数字和来源；来源不清或未检查不得说完全准确。合计不一致列异常，不能倒推改写原值。
5. 输出新 Excel 和待核实清单，说明处理范围、识别方式、实际检查和未检查项，不覆盖原文。涉及真实数据是否发送到平台/OCR 服务按实际权限与组织要求执行。

`tools/document-to-excel/docx_tables.py` 为简单 DOCX 表格文字提取工具，不执行 OCR，不提取表格外文字、页码、页眉或图片；表格中包含合并单元格、嵌套表格或无法处理的结构时拒绝，不假定数字正确。文件只读、输出独占新建，输出结构化表格、单元格坐标明细及含数字原文复核清单，以文本保存并回读校验；结构化表格不保留原格式，复核清单按字符是否为数字筛选，并不代表已核对或覆盖所有模糊数字。用户需结合原文复核；遇到 PDF、照片、纯正文或复杂表格，使用当前平台工具或明确说明不能完成。

可搜索 PDF 的文字层可使用 `tools/document-to-excel/pdf_text_to_excel.py`，依赖 pypdfium2 与 openpyxl。它按 PDF 页导出原文分块、数字候选、上下文与页内字符偏移，并在同值唯一、搜索文本和字符范围一致时附加 PDF 页面坐标（PDF canvas units）辅助定位；重复值、字符索引不一致或边界框异常均留空并标记未定位。坐标不是视觉识别或数字正确性证明。工具不自动恢复表格行列，也不做 OCR；PDF 内作为图片的文字、矢量转曲文字和批注可能未提取。逐页状态会区分有文字层与未发现文字层；混合 PDF 中无文字页可能是扫描页、空白页或字体编码异常，不能假定业务内容为空。全 PDF 未发现文字层时停止，改走扫描件 OCR/人工流程。输出使用新路径，临时 XLSX 回读核验及源哈希通过后才以硬链接发布；文件系统不支持硬链接时停止。需逐页对照原 PDF 检查文字顺序、数字、标点、空白和遗漏；本地合成样例测试不代表真实 PDF 的提取准确率或版面还原能力。


## DOCX 特殊行内内容边界

DOCX 仅提取 `w:t` 普通文本节点；单元格中的未知 Word 行内节点（包括可能承载可见字符的 noBreakHyphen/softHyphen）及 `mc:AlternateContent` 替代内容会拒绝处理，避免字符被静默省略或重复。复杂文档需人工确认转换方式。

## DOCX 结果安全发布

简单 DOCX 表格导出先写入输出目录中的临时 XLSX，完成源文件哈希复核、结构化明细/表格/数字复核清单回读后，再以硬链接原子发布到目标路径。遇到写入、回读或源文件变化时不发布目标文件，并清理临时文件；若文件系统不支持硬链接或目标已存在则停止，不覆盖已有结果。中断时可能遗留 .ledger-docx- 临时文件，需按原文资料保护要求检查。该流程只证明输出结构与提取结果一致，不证明 DOCX 中的数字业务含义正确。


## 括号金额分组

PDF 文字层候选允许标准括号金额，例如 `(88.00)`、`(1,234.56)`，括号内千位逗号必须按三位分组；`(12,34)`、`(1234,567)` 等异常分组不会被当作候选。此规则只用于筛出复核候选，不会自动将括号转换为负数或计算金额；须按原 PDF 字符逐项确认。

## PDF 数字候选的边界

PDF 文字层数字候选要求完整词项边界：数字不得与字母、下划线、点号或逗号粘连。这样可避免把 `123ABC`、`1.2.3`、`1,23` 等混合或异常格式切成看似完整的数字片段。它仍是候选筛选，不是数字识别或格式校验；遇到不规范数值时必须回看页面原文，工具不会替用户修正或猜测。PDFium 返回的 CR/CRLF 行分隔会统一为 LF，以避免 XLSX/XML 回读时行分隔被规范化；文字字符和段落边界保留，字符偏移按规范化后的导出文本计算。


## DOCX 中文金额复核候选

数字复核清单保留含阿拉伯数字或中文大写金额数字的单元格；常用中文数字只有在同格同时出现数位或币值单位时才列为候选，例如“三百五十元”。普通序数“第一项”不因包含汉字“一”而触发。该筛选只用于提示人工复核，不解析中文金额或转换成数值。


## PDF 全角数字候选

PDF 文字层候选支持全角数字与全角千分位/小数点符号，候选字符串保留 PDF 提取原文，不做 NFKC 转换；例如 `１，２３４．５６` 作为一个候选。错误分组（如 `１，２３`）因边界守卫而整体排除，不拆出局部数字。候选仅用于人工定位与复核，不证明数字含义或正确性。


## PDF 文字上限先于候选扫描

PDF 提取器对每页累计文字量在数字候选正则扫描和字符坐标搜索前检查。总量超过配置上限时立即停止，不继续对超限页面枚举候选或生成结果。此限制只避免超限文本上的额外处理；PDFium 读取页面文字本身仍需先完成，不能视为完全防止大型/恶意 PDF 的资源消耗。


## PDF 中文金额复核候选

PDF 文字层候选会保留含中文数位/金额单位的原始片段，例如“人民币叁佰伍拾元整”“三百五十元”“负壹仟贰佰元整”“三万零五百”以及带中文币值单位的阿拉伯数字“人民币1,234.56元整”。它不解析、换算或确认数值；普通序数（如“第十二项”“第一百项”）与单独中文编号不因包含数字字符自动成为候选。只要原文表达不规范或上下文含义不明，需回看原页并人工判断。合成回归覆盖这些候选与序数排除，不代表所有中文金额写法均可识别。


PDF 中文金额回归除候选正则外，还以虚构文本页替身走过提取、来源偏移、工作簿发布和回读链路，检查中文金额原文及待人工复核状态保留、普通序数不成为候选、源文件哈希不变。该测试隔离 PDFium 字体/字形解码，只验证候选到 Excel 的数据链，不替代实际嵌入中文字体的 PDF 渲染/提取兼容测试。


PDF 中文字体兼容回归另用 PyMuPDF 1.28.2 生成带简体中文 china-s CID 字体的虚构 PDF，并走真实 PDFium 提取及 Excel 发布链，核对文字层、中文金额候选、偏移/坐标、人工复核状态和源哈希。PyMuPDF 只在 GitHub Actions 中作为测试样例生成器，未加入技能运行依赖。回归通过只证明该固定生成方式和字体样例可用，不覆盖所有 CJK 编码、子集字体或扫描 PDF。


## DOCX 源哈希资源边界

DOCX 提取入口在计算输入哈希前检查 100 MiB 文件上限；哈希读取中再次累计实际读取字节，若文件在预检后增长超过限制则停止。随后仍执行 ZIP 条目、成员/总解压大小、正文 XML 与单元格数量检查。虚构回归验证超限时哈希函数未运行，以及文件大小检查后增长会被哈希器拦截。边界检查降低大型输入的无谓读取，不是对 ZIP/XML 全部攻击面的安全证明；输出数字候选仍须人工对照原文。


## 可搜索 PDF 输入字节限制

可搜索 PDF 转 Excel 的入口在计算源 SHA-256 前拒绝超过 100 MiB 的输入；哈希过程也累计实际读取字节，文件在检查后增长超限时停止。此检查早于 PDFium 解析，与页数和抽取文字量上限互补。虚构回归验证超限 PDF 不进入哈希/提取，以及文件在初始大小检查后增长时哈希器仍拒绝。此项不构成 PDFium 沙箱或全面格式验证；所有数字候选仍需逐字符对照原页。


DOCX 数字候选筛选包含“廿、卅、卌”等中文简写数词（如“廿元”），仅将原文送入人工复核，不解析或改写金额；此覆盖不代表穷尽所有地区、历史或行业数字写法。


DOCX 数字候选还会保留“廿、卅、卌”单独出现的原文（如“廿七”），送入人工复核，不解析或改写；可能增加非金额候选，仍不保证覆盖所有地方性数词。


## 当前版本候选覆盖

可搜索 PDF 和 DOCX 表格的数字复核候选均会保留“廿、卅、卌”等简写数词，包括没有金额单位的形式；候选只用于人工定位和逐字符核对，不解析、换算或确认金额。XLSX→CSV 遇到底层数值超过 15 位有效数字时停止，以避免把可能已受 Excel 精度影响的值当成可信原值。
