# 本地 OCR 试验边界 v0.20

v0.30 准备检查：用拟运行 OCR 的同一解释器执行 `python tools/local-ocr/recognize_image.py --check-runtime`，检查固定版本及三份模型哈希。无需图片或输出路径，不加载识别引擎，不下载模型；版本不符、缺模型或哈希不一致即停止。依赖导入自检另用 `tools/check_environment.py --task local_ocr` 或 `--task pdf_pipeline`；两类检查都通过仍需实际虚构识别与人工复核，不能据此报告数字准确。

该入口使用 RapidOCR 和 ONNX Runtime，本仓库不包含运行时或模型，先在独立环境自行按 `tools/local-ocr/requirements.txt` 准备依赖；工具不负责安装、下载或修改系统。来源：https://github.com/RapidAI/RapidOCR ，代码及模型按上游说明使用 Apache-2.0；实际依赖及模型的许可应分别核对。运行前逐项检查内置默认模型的名称和 SHA-256，不符合即停止。运行时在 Python 进程中阻断 socket 连接，仅为进程级措施，不能证明操作系统隔离或平台不接收数据。

本工具只读取单张本地 PNG/JPEG，生成含文本、检测框、分数、源文件名和 SHA-256 的 JSON；每条均标待人工核对。检测框不是表格单元格，不自动识别表格结构、分配金额或输出财务结论。模型分数不保证金额正确，空白结果也不代表原图一定空白。扫描 PDF、多页、合并单元格和其他文件须用其他已确认能力。

2026-11-11 在单机 CPU 和合成数据上测试：清晰/模糊/轻旋转单行样例数字 27/27，两个合成表格中根据已知单元格边界计算数字 12/12；低质量小字样例 22/24，出现标点及数字误识别。表格定位依赖测试时预先给出的坐标，不能视为自动表格识别测试。样本量小且人工合成，不能估计真实准确率，仍仅限虚构试用。

2026-11-14 使用 v0.36 固定版本/模型哈希通过后的实际识别入口，对 24 张虚构挑战图再测：数字字符及分隔符完全一致 22/24。两项低质量图片仍有误识别：`1,234.56` 被识别为 `1.23456`，`(88.00)` 被识别为 `(86.00)`。运行时/模型准备成功不代表识别可靠；所有结果仍须人工逐字符比对。样本为人工生成、数量有限，不可外推为真实单据准确率。具体结果不随公开包发布。

若 PDF 有可提取文字层，先评估 `tools/document-to-excel/pdf_text_to_excel.py`；它不运行 OCR。无文字层或混合扫描页按页码状态转入 OCR 或人工查看；不得因某页没有提取文字就把它判断为空白。


## v0.21 简单网格表实验
单张虚构图片可依次调用 `recognize_image.py image.png ocr.json`、`table_grid.py image.png ocr.json grid.json` 和 `export_review.py image.png grid.json review.xlsx`。前两步需要指定 OCR 环境（含 OpenCV/Numpy），第三步需要 Python 与 openpyxl。工具不安装依赖，输出独占创建；图像和中间结果按 SHA-256 核验。

只尝试图片中单个清晰、水平垂直的完整线框网格，不能保证辨认所有合并或缺失线、多表、无边框、倾斜或复杂布局；结果无论是否检测成功均不代表单元格定位正确。跨边界/未归属文本单列，所有单元格包括空白均标记待人工核对原图；不得按置信度自动确认、填入真实台账或隐藏遗漏。图片/PDF 页码和表格归属需人工提供；当前工具不合并多页、不读取 PDF。

本机两页独立的简单合成表格图片验证自动定位，两页共 12 个包含数字或为空的预设格与真值一致；同时验证跨边界识别框单列、非表格图片及错误来源哈希拒绝、复核 Excel 回读、公式样文本按字符串输出。样例规模小，未证明真实票据、扫描表格或模糊图片可用。


## v0.22 多页 PDF 试验
在事先准备指定依赖和模型的独立环境中，运行 `python tools/local-ocr/pipeline_pdf.py 输入.pdf 新建输出目录`。工具只接受 1–20 页及单页像素上限，每页依次渲染 PNG、执行本地 OCR、检测一个简单线框表，全部页成功后导出 `待人工复核.xlsx`，并保留每页图片、OCR 和网格 JSON 供追溯。输出目录必须不存在，失败时可能留下部分中间文件；检查后换新目录，不自动删除。输出资料包含原始页面内容，按组织数据处理要求保护。

来源记录包括 PDF 哈希、页码、页面图片及中间结果哈希；每格及未归属片段都标待核对，空白不代表原件为空。该工具不适用于不能确认可用的无框表、多个表格、复杂跨行合并、旋转页面或其他复杂版式；检测通过也不保证数字和表格结构正确。任一页检测失败则停止，不输出最终 Excel。不能将试验用作真实业务自动录入。

本机以一份两页虚构扫描式 PDF 做端到端测试：12 个包含数字或为空的预设格与真值一致，24 格均待复核；缺页、OCR 结果被篡改、目标已存在及第二页不是表格的情况均阻止最终生成或覆盖。样本有限，仅代表该本机环境。


## v0.23 不完整边框与可选原页预览
网格定位针对格内未识别的较长部分横线/竖线作保守拦截，以减少部分缺线或合并格被误当完整网格；长文本笔画等也可能误触发，无法发现完全缺失的边线，不代表完整或准确。判断结果和未归属内容均须人工核对；失败时不猜结构。

多页 PDF 管线默认不嵌入页面；明确需要时可在原命令末尾加 `--embed-page-previews`，输出工作簿会增加每页缩略图供定位。预览会把整个 PDF 页面图像复制进 Excel，即使图像中内容不在提取表格范围内；处理与分享前必须符合原资料授权与数据保护要求。缩略图分辨率有限，不可作为数字确认依据，仍需打开原 PDF 原尺寸复核。工作簿、页面 PNG 和中间 JSON 都可能含敏感原文，依据本地规定保管。

本机虚构样例测试：部分横/竖边框拦截、完整网格回归、两页 PDF 含/不含预览分别导出；输出文件的缩略图字节回读、页码和数字样例核验通过。未进行 Excel/WPS 页面排版目视验收，也未测试真实扫描件。


## v0.24 人工复核与记录（虚构试用）
复核工作簿的 `逐格复核` 新增 G 列“人工复核选择”和 H 列“人工修正原文”。逐格对照原 PDF 原尺寸，选择 `原文一致`、`人工修正`、`原文为空` 或 `无法辨认`；仅选择人工修正时填写 H 列，长编号、金额原样按文本输入。下拉只是便利，不能代替程序检查；用户应避免直接改写 OCR 原文、行列和来源。

保存复核表的新副本后可运行 `python tools/local-ocr/collect_review.py 输入.pdf 页面目录 复核副本.xlsx 复核记录.xlsx`。程序验证 PDF、页面、OCR、网格来源链及逐格原始记录，并要求每格做出明确选择；遗漏、来源变化、修正值被保存为数值或公式、未归属片段均停止，不覆盖输入。`无法辨认` 项可保留，但汇总中计入未解决，不能当作已确认。工具只记录使用者的声明，无法证实人是否实际看过原件，不代表财务核准。输出包含敏感原文，按授权保管。旧版复核表缺少 G/H 两列，须用 v0.24 重新生成；暂不提供自动迁移。

虚构样例覆盖未选择、长编号作为文本保留、数值型修正拒绝、识别原文变更拒绝、不同复核状态和不覆盖输出；尚未用真实资料或由同事验收。
