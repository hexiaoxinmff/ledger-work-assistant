# 平台实用验收（全部虚构资料）

此测试区分包内脚本运行与平台自主调用，不能用本机脚本通过替代平台验收。不使用真实业务文件。安装技能后在新会话使用以下文字，测试者自行确认技能所在目录；不要假设技能已经自动加载。

## 可复制需求

请用当前已安装的台账助手，处理该技能目录 tools/tests/fixtures 下的三个虚构文件 acceptance.csv、acceptance.tsv、acceptance_semicolon.csv。第三个文件明确使用分号分隔。请各转为独立 Excel，再从 Excel 转回对应文本格式；另存到本次新建的测试目录。

所有编号和金额原文都要完整保留，包括前导零、长编号、12.30、-0.00、空金额及跨行备注。先检查当前解释器是否适用于转换任务，满足条件就使用包内转换器，保留实际调用命令、退出码和结果路径。缺依赖时先寻找已经可用的解释器；不要安装依赖或改源码。如果无法执行，请明确说明停在哪一步。

完成后重新读取实际生成的文件，逐条对照三个原文件，说明记录数、字段数、原文是否保留，以及输入 SHA-256 前后是否一致。再尝试把其中一份转换写入已经生成的同名结果，核对工具拒绝且已有结果哈希不变。不得仅凭新文件名声称独占创建，不把零金额与空金额视为相同，不声称已经做过未执行的核验。

最后报告技能版本、自动加载还是手动读取、实际解释器、是否调用了包内脚本、原始报错及仍未验证的内容。

## 测试者核对

每份文件均为 3 列、3 条数据记录（含表头共 4 条逻辑记录），不是按物理文本行数计数。三份解析后的内容相同：首条 ID 为 001234567890123456789，金额文本 12.30，备注为 first 与 second 两行；第二条 ID 为 00042，金额文本 -0.00，备注空；第三条 ID 为 00043，金额空，备注 pending。

Excel 应保留 ID 的文本类型和金额原文；文本格式文件本身不保存类型，直接用电子表格软件打开的行为需另测。预期同名输出被拒绝且内容不变。报告说明“实际调用、回读及哈希”才有相应执行证据；只有自述流程或文件存在不足以证明通过。

禁止安装导致缺依赖时应记录为环境未满足，不记为转换算法失败。未自动加载须标手动读取；未真正运行不得填写通过。通过此测试仍不等于 OCR、对账、Excel/WPS 界面或真实业务验收。
