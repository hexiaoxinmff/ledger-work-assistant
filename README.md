# 费用与收款台账整理助手

一个平台中立的试用技能，帮助使用者按平台能力转换常见文档、表格、PDF 和图片格式，并整理费用、收款等表格，保留来源并列出待核实事项。不能代替财务审核，不自动入账、付款、开票或发送。

## 安装和使用

当前技能版本：v0.88。先在新会话确认实际加载的 `SKILL.md` 版本；直接阅读本地文件与平台自动加载是不同状态。通用虚构试用需求和核对标准见 [平台验收](ledger-organizer/references/platform-acceptance.md)，三份样例随包位于 `ledger-organizer/tools/tests/fixtures/`。

本机虚构回归入口：`python ledger-organizer/tools/run_checks.py`。默认执行基础环境/样例/转换/Word 提取测试；对账业务规则测试用 `--suite ledger`（需预装 pandas、openpyxl、PyYAML），PDF 文字层转表测试用 `--suite pdf-text`（需预装 pypdfium2、openpyxl），OCR 相关测试用 `--suite ocr`，全部用 `--suite all`。各组依赖须事先满足，报告保留失败、超时和未运行项目，不能将部分通过当成全功能通过。这些测试不包含真实账目、平台自主调用、界面或 OCR 准确率验收。

在仓库根目录运行以下命令检查本次要用的解释器，不自动安装依赖：

```text
python ledger-organizer/tools/check_environment.py --task table_conversion
```

报告包含实际解释器与工具入口。后续命令中的 `python` 应使用同一个解释器；检查失败须如实记录，不能当成转换已通过。其他任务可用 `--help` 查看；OCR 还需指定版本、模型和实际识别验证。

使用纯虚构、明确三列的包内样例试转，结果路径必须尚不存在：

```text
python ledger-organizer/tools/format-conversion/convert_table.py ledger-organizer/tools/tests/fixtures/acceptance.csv acceptance-result.xlsx --expected-columns 3
```

这是转换命令示例，不会安装技能或证明平台已自动调用。转换后仍应重新读取结果并逐项核对。首次试用先完成样例验收，再评估本人任务所需规则和未覆盖限制。

下载本仓库后，将 `ledger-organizer` 文件夹按所用 Agent 平台的技能安装方式导入，或让支持读取文件的 Agent 阅读 `ledger-organizer/SKILL.md`。具体目录、自动加载、联网和文件访问能力因平台而异，需在目标环境测试。可先用虚构样例提供两张表、确认字段和规则，再要求保留来源、生成复核清单。

对账计算使用根据输入位数和记录数量扩展的 Decimal 精度，避免大额汇总受默认 28 位上下文影响；大额虚构台账端到端回归已纳入 ledger 测试组。此项仍受解析器金额精度范围约束，不代表真实账务验收。

技能内含有限测试的 Python 对账适配副本；运行需要 Python、pandas、openpyxl、PyYAML，实际依赖和平台权限须另行检查。其结果可选表格或附加结果项柱状图；结果项数量不等于交易笔数。脚本当前仅用虚构数据测试，不用于真实账目。

DOCX 转 Excel 会在计算源哈希前拒绝超过 100 MiB 的文件，并在哈希读取中再次限制实际字节数，防止检查后文件增长造成无界读取。此处只说明资源边界；DOCX 数字候选仍是原文提示，须人工复核。

可搜索 PDF 转 Excel 会在哈希和解析之前拒绝超过 100 MiB 的文件，并在哈希时限制实际读取字节；页数、提取文本和数字候选均另有上限。上述限制仅控制资源规模，不验证数字正确性。候选必须逐字符对照原 PDF。

CSV/XLSX 互转会在哈希前检查 100 MiB 文件上限，并在哈希期间限制实际读取量；超限文件或读取期间增大的文件停止处理。仍须对照原表核对编号、金额、日期和格式显示。

扫描 PDF OCR 在哈希和 PDFium 渲染前检查 100 MiB 输入上限，并在哈希中限制实际读取量；各页另有限制。该保护不证明识别精度，数字必须对照原件复核。

## 按需发现其他技能

当前任务缺少能力时，优先使用平台已有技能；必要时可用通用关键词进行只读搜索，评估候选后按平台权限与用户授权使用。搜索关键词会发送给外部服务，不应包含个人或业务数据。详情见 `ledger-organizer/references/skill-discovery.md`。

本地 OCR 与网格映射共用图片头预检（图片最大 100 MiB、2500 万像素）；网格 OCR JSON 限制为 25 MiB 和 10 万条。限制在解码前执行并防止文件变化时无上限读取，但不代表 OCR 识别准确或真实资料已验证。所有识别结果仍须对照原图人工复核。

## 文档转 Excel

简单 DOCX 文本表格可使用 `ledger-organizer/tools/document-to-excel/docx_tables.py`，输出按表、行、列定位的单元格明细，数字原文以文本保存并回读校验。结果先在临时文件中完成源哈希与工作簿回读检查，再原子发布，不覆盖已有结果；该工具不含 OCR，不处理扫描件、PDF、文档正文、合并表格和图片。其他形式依赖平台实际可用的文档或识别工具。所有结果必须结合原件复核；目前只用虚构数据测试。

## 常见文件格式转换

技能根据任务和当前平台能力选择文档、PDF、表格及图片转换工具；不同平台的支持情况需实测。格式转换后的数字、文件结构与页面呈现需要按任务核验，详见 `ledger-organizer/references/format-conversion.md`。本技能不自带所有格式的转换器或 OCR。

包内提供受限的 CSV/TSV 与 XLSX 本地互转脚本 `ledger-organizer/tools/format-conversion/convert_table.py`。TSV 固定制表符，CSV 默认逗号，可明确指定 `--delimiter semicolon` 或 `--delimiter tab`；已确认列数时使用 `--expected-columns`。显示格式可能影响数字含义时默认停止，只有明确接受底层值导出后才使用 `--allow-display-loss`。源内容按文本保存及回读核验，文本导出不保留类型，直接在表格软件打开仍可能改变长编号。更多限制见转换说明。

简单 DOCX 表格转换生成结构化表、来源明细及含数字原文复核清单；筛选覆盖常见中文数位单位形式（如“十元”“拾元”“百元”），但仅作候选，筛选不代表已核对，也不承诺覆盖所有数字写法。特殊符号、域标记、脚注/尾注引用、内容控件等不支持结构会停止，需另选方式并人工确认；该检查不能穷尽所有 Word 结构。DOCX 另有文件大小、ZIP 成员、解压总量、正文 XML 和单元格数上限，详情见工具常量；超限会停止。环境自检不带参数时仅检查模块和文件能否发现，带 `--task` 才实际探测相应依赖导入。

可搜索 PDF 的文字层可用 `ledger-organizer/tools/document-to-excel/pdf_text_to_excel.py` 导出逐页原文、页码状态、数字候选和可用的页内坐标（PDF canvas units）；坐标仅在数字唯一且字符范围校验通过时提供，不能证明数字正确。不做 OCR，也不猜表格列。图片文字、矢量转曲文字和批注可能未提取；扫描页逐页标明，整份没有文字层则停止。使用前运行 `python ledger-organizer/tools/check_environment.py --task pdf_text`；提取的每个数字仍须对照 PDF 原页核对。

## 本地图片 OCR 实验

包内提供单图识别脚本及 `prepare_models.py`。使用者显式运行准备脚本时，它会在已安装 RapidOCR 的 models 目录中下载三份固定模型并校验 SHA-256；不安装依赖、不创建目录、不覆盖已有文件。识别结果保留原文、位置和待人工复核状态；GitHub Actions 会用临时生成的虚构数字图像运行固定真实模型冒烟测试，并测量 8 种数字/金额/日期写法；测量结果列在 Actions 摘要并保存 7 天，精确率不作为自动放行门槛，也不代表真实资料准确率。完整限制见 `ledger-organizer/references/local-ocr.md`。

虚构 OCR 输出可用 `ledger-organizer/tools/local-ocr/evaluate_accuracy.py` 与真值清单评分，统计金额/日期/编号的完全匹配率、CER 和漏/多识别行；评分结果仍全部待人工复核，不能用于确认真实数据。

实验功能可对单张简单线框表格图片尝试定位网格并导出复核工作簿；OCR 坐标会检查四角结构、有限数值、图片范围及正面积，异常时不生成网格文件；仅限虚构样例，依赖 OCR/OpenCV 和 openpyxl。所有识别内容及空格需对原图人工核对，多页 PDF 和复杂表格暂不保证支持。详见 `ledger-organizer/references/local-ocr.md`。

实验功能还可尝试 1–20 页、每页一个简单线框表的虚构 PDF，输出带页码的复核工作簿和中间页面文件；任何页面失败会停止，所有格子必须人工核对。依赖、隐私和适用范围见 `ledger-organizer/references/local-ocr.md`。

PDF 一键流程在渲染前自动检查 OCR 版本和模型哈希；也可单独运行 `python ledger-organizer/tools/local-ocr/recognize_image.py --check-runtime`，此检查无需图片，不运行识别，不证明引擎初始化或准确率。依赖不随仓库下载，代码存在也不等于 OCR 环境已准备。

CSV/TSV 转换还会拒绝 XLSX 文本转 CSV 时可能被当作公式的前缀，包括换行和全角公式符号；普通负数保留。CSV/TSV 转换、PDF 复核表及复核汇总采用临时文件校验后不覆盖发布，目标目录需要硬链接支持。强制中断可能遗留含原文的临时文件，按资料授权处理；其他输出工具不自动具有相同保护。

多页 PDF 复核默认不嵌入原页；如用户明确需要，可选择嵌入原页缩略图辅助定位。缩略图包含完整页面，可能包含表格以外的内容，分享前需按资料授权处理；数字仍以原 PDF 原尺寸人工复核。

PDF 虚构样例复核表提供逐格人工选择和文本修正；可选工具汇总复核记录并检查来源和未完成项。工具记录使用者声明，不能证明人工实际核看原件或财务结果正确。


OCR 的合成图像条件测量还包含预处理诊断：仅比较临时生成图上的原图、自动对比度和固定阈值图像，记录两种输入哈希，不改写用户图片或自动应用处理。结果仅用于观察固定合成样例，不能证明真实资料识别改善。

2026-11-15 合成预处理对比实测：低对比/JPEG 负数图原图与两种变换合计单框完全匹配 0/6，均发生拆框，未显示能可靠恢复完整金额的方案。因此技能不自动预处理真实图像；详情和限制见本地 OCR 说明。


可搜索 PDF 数字候选现包含部分中文金额原文以及带中文币值单位的阿拉伯数字金额原文，仍不作数值转换或准确性判断；普通序数不会仅因汉字数字列入候选。支持范围及边界见 PDF 转换说明。


PDF 中文金额测试现包含使用 PyMuPDF 生成的简体中文 CID 字体虚构 PDF，并经 PDFium 实际提取到 Excel 回读；PyMuPDF 只用于 CI 生成样例，不是技能运行依赖。仅验证固定字体样例，不能推广为所有中文 PDF 都可正确提取。


XLSX→CSV 对超过 15 位有效数字的底层数值会停止转换，避免把可能已受 Excel 精度影响的长数字当作可信原值；核对原件并按文本保存已确认值后再转换。
